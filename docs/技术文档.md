# Kill the C · 技术文档

> 版本 1.0.0 ｜ 平台 Windows 10 1809+ / Windows 11 (x64) ｜ 安装包 5.0 MB

## 1. 项目目标与硬约束

| 目标 | 说明 |
| --- | --- |
| 交付形态 | 单一 `.exe` 安装包，支持安装 / 卸载，进入「应用和功能」列表 |
| **体积硬约束** | 安装包 ≤ 20 MB（实测 **5.0 MB**，余量 75%） |
| 界面风格 | 苹果式简约科技风，局部拟物化（金属质感圆环、凹槽进度条、滑块分段控件） |
| 图标 | 黑色系，一把刀把磁盘切成两半 |
| 安全底线 | 所有清理动作二次确认；默认进回收站；回收站清空再次确认；白名单与系统保护区双重校验 |

## 2. 技术选型（以及为什么）

| 候选方案 | 结论 | 原因 |
| --- | --- | --- |
| Electron / NW.js | ❌ | 运行时 100 MB+，直接违反体积约束 |
| .NET WPF / WinForms 自包含 | ❌ | 自包含发布 60 MB+；依赖系统 .NET Framework 又无法保证现代 UI |
| Python + PyInstaller + Qt | ❌ | 运行时 + GUI 框架 30 MB 起步 |
| Tauri (Rust) | ❌ | 需 MSVC 工具链（数 GB），构建链过重 |
| Node.js SEA / Bun 单文件 | ❌ | 基础运行时即 70–90 MB |
| **Go (纯 syscall，无 cgo) + WebView2** | ✅ **采用** | 单文件 exe 7.2 MB，零运行时依赖；WebView2 在 Win10/11 已预装；Go 可直接调用全部 Win32 API |

### 2.1 采用的技术栈

| 层次 | 技术 |
| --- | --- |
| 语言 | Go 1.25（`CGO_ENABLED=0`，纯 syscall 调用 Win32） |
| 窗口与渲染 | Microsoft Edge **WebView2**，通过纯 Go 绑定 `github.com/jchv/go-webview2`（自带 `go-winloader`，把 WebView2Loader 从内存加载，**无需随包分发 DLL**） |
| 前后端通信 | 进程内 `net/http` 服务，仅监听 `127.0.0.1` 随机端口；实时进度用 **SSE**（Server-Sent Events） |
| 前端 | 原生 HTML / CSS / JavaScript（无框架、无构建步骤），内嵌进 exe |
| 图标与版本信息 | `go-winres` 生成 `.syso` 资源 |
| 安装程序 | 自研纯 Win32 安装器（同样零依赖，5 MB 内含全部应用负载） |

### 2.2 为什么把界面放在 WebView2 里

Go 原生 GUI（Fyne / Walk / 手写 GDI）要么体积大，要么很难做出「苹果式简约 + 拟物化」的质感。
WebView2 让界面用 HTML/CSS 表达（渐变、毛玻璃、内阴影、贝塞尔动画全部可用），
而系统里的 WebView2 运行时不需要我们分发，体积成本为 **0**。

代价是：Windows 10 早期版本（1803 以前）可能没有 WebView2 运行时。
程序做了降级处理——若 WebView2 初始化失败，自动改用系统 Edge 的 `--app` 模式承载同一套页面。

### 3.1 为什么用「本地 HTTP + SSE」而不是 Go↔JS 绑定

浏览器端的绑定方案（`webview.Bind`）在不同 WebView2 版本上行为不一致，
而本地 HTTP 是**完全确定性**的：请求-响应 + SSE 流式推送，天然支持实时进度、
可取消、可在浏览器里独立调试（开发期直接开浏览器就能调 UI）。
服务只监听回环地址，同时用随机会话令牌（注入到页面 `<meta>` 中，所有 `/api/*` 请求校验 `X-KTC` 头）阻止本机其它进程越权调用。

## 5. 核心机制

### 5.1 并行遍历引擎（`internal/fsx`）

全盘扫描最大的敌人是「慢」与「踩坑」。引擎做了这些事：

- **动态工作队列**：基于 `sync.Cond` 的任务池（默认 2–8 协程），
  彻底避免「固定大小 channel + 递归投递」的经典死锁。
- **长路径**：路径 ≥ 240 字符时自动加 `\\?\` 前缀（UNC 用 `\\?\UNC\`），
  突破 MAX_PATH 限制。
- **重解析点防护**：目录会同时检查 `DirEntry.Type()&ModeSymlink` 与
  `FILE_ATTRIBUTE_REPARSE_POINT(0x400)`，防止 junction 造成的无限循环与重复计数。
- **可中断**：`context` 取消后 500ms 内所有协程退出。
- **进度节流**：每 N 个文件回调一次，避免高频事件压垮 SSE。

实测：本机 C 盘 **550,079 个文件 / 80.8 GB，22.0 秒**完成全盘分类扫描。

### 5.2 分类与风险评估（`internal/classify`）

**16 个文件大类**：临时文件、缓存文件、日志、转储、备份与副本、更新残留、安装包、
视频、图片、音频、压缩包、文档、开发文件、程序文件、系统文件、其他。

**4 个风险等级**：`安全 / 谨慎 / 高风险 / 受保护`
**4 个优先级**：`P0 立即可清理 → P3 保守不清理`

判定顺序（短路设计，先保护后清理）：

1. **系统保护区**（`C:\Windows\System32`、`WinSxS`、`servicing`、`Fonts` 等 30+ 前缀）→ 受保护，永久不可勾选
2. **系统根目录关键文件**（`pagefile.sys`、`hiberfil.sys`、`bootmgr`…）→ 仅展示
3. **回收站** → 安全 / P0
4. **垃圾目录指纹库**（40+ 条）：`\Temp\`、`Prefetch`、`SoftwareDistribution\Download`、
   浏览器 Cache/Code Cache/GPUCache、`CrashDumps`、`WER`、`Thumbcache`、`Windows.old`…
5. **扩展名风险**（`.sys/.drv/.efi/.mui` → 系统；`.dll/.exe` → 程序文件）
6. **陈旧度加成**：体积大且超过 180 天未修改 → 提升优先级
7. **个人数据目录**（桌面/文档/图片/视频/音乐）→ 谨慎 / P3
8. **程序安装目录** → 高风险
9. Windows 目录内未命中指纹的内容 → 高风险且默认不可勾选

### 5.3 两种清理粒度

| 粒度 | 触发方式 | 后端行为 |
| --- | --- | --- |
| **按类目整类清理** | 勾选类目复选框 | `clean.RunByCategory` 重新遍历磁盘，删除该类目下**全部**匹配文件（不受列表展示上限影响） |
| **按文件精确清理** | 在展开的列表中勾选具体文件 | `clean.Run` 逐个删除指定路径 |

采用双粒度是为了解决一个真实矛盾：扫描无法把几十万个文件全塞给前端，
但用户点「清理缓存」时期望的是**整个缓存被清掉**。列表只展示体积最大的若干项并明确标注，
勾选类目则代表「整类处理」。

### 5.4 清理执行（`internal/clean`）

- **默认送回收站**：`SHFileOperationW` + `FOF_ALLOWUNDO | FOF_SILENT | FOF_NOCONFIRMATION | FOF_NOERRORUI`，
  路径以双 NUL 结尾的多字符串传入。
- **永久删除**：`DeleteFileW`（长路径加 `\\?\`），遇到只读属性（错误码 5）先清属性再重试一次；
  目录树自底向上 `RemoveDirectoryW` 清理空壳。
- **逐文件进度**：每删一个文件推送一次「当前处理的文件名称」，前端实时显示。
- **执行前二次校验**：白名单 / 受保护路径 / 盘符根目录 / 关键系统目录，
  即使前端传入异常清单也会被跳过（实测拦截生效）。
- **回收站**：`SHQueryRecycleBinW` 读占用，`SHEmptyRecycleBinW` 静默清空（清空前必须用户确认）。

### 5.5 重复文件（`internal/dup`）

**扫描范围**：默认**整个系统盘**（可在界面上切换为「仅个人目录」）。
为避免扫出一堆无意义甚至危险的「重复项」，以下位置会被跳过：

- 系统保护区：`Windows`、`Program Files`、`Program Files (x86)`、`$Recycle.Bin`、
  `System Volume Information`、`Recovery`、`PerfLogs`、`ProgramData\Microsoft\Windows`
- 结构性重复：`AppData\Local\Packages`（UWP 沙箱，系统托管）、`node_modules`、`.git`
- 白名单目录、重解析点

**三级过滤**，兼顾速度与准确性：

1. **体积分组** — 只有同尺寸文件才可能是重复（< 1 MB 的文件默认跳过，可调）
2. **快速指纹** — 首 64 KB + 尾 64 KB + 文件大小 → CRC64；
   ≤ 128 KB 的小文件直接全量 SHA-256，跳过第三级
3. **全量 SHA-256** — 仅对第二级仍有冲突的文件做完整哈希（4–8 协程并发）

结果按「可释放体积」倒序；每组默认保留**修改时间最早**的一个，
支持在组内用单选切换保留项。「一键选中所有重复文件」= 选中所有非保留副本。
结果超过 600 组时只列出可释放空间最大的部分，并在界面上明确提示。

整盘扫描需要逐个读取文件内容，实测本机（7,600 个 ≥1 MB 的候选文件 / 约 38 GB）
第一次约 2.6 分钟、文件缓存命中后约 37 秒；过程中有实时进度且可随时中止。

### 5.6 卸载残留（`internal/residue`）

**证据索引**（判定「哪些名字代表已安装」）：

- 注册表三处 `Uninstall` 项（HKLM、HKLM\WOW6432Node、HKCU）的
  `DisplayName` / `Publisher` / `InstallLocation` / `UninstallString` / `DisplayIcon`
- 上述路径字符串中的每一级目录名
- `Program Files`、`Program Files (x86)`、`%LOCALAPPDATA%\Programs` 下的现有目录名

**扫描位置**：`%APPDATA%`、`%LOCALAPPDATA%`、`%LOCALAPPDATA%\Programs`、
`%PROGRAMDATA%`、文档目录、开始菜单（当前用户 + 全局），
非系统盘时额外扫描盘根目录。

**打分与置信度**：目录名未命中证据索引（+2）、位于典型残留位置（+1~+2）、
含缓存/配置等残留特征文件（+2）、接近空壳（+1）、超过 120 天未修改（+2）、
含版本号子目录（+1）；体积超 2 GB 或位于程序目录则减分并提示。
得分 ≥ 6 → 高置信，≥ 3 → 中置信，低于 3 直接丢弃（宁缺勿滥）。

同时还识别两类「看得见的残留」：
- **注册表孤儿项**：卸载记录指向的安装目录已不存在
- **失效快捷方式**：解析 `.lnk` 的目标路径，目标不存在即报告
  （`.lnk` 解析自行实现，ANSI 路径经 `MultiByteToWideChar(CP_ACP)` 正确解码中文路径）

实测：本机扫描出 35 项候选 / 731.7 MB，全部为待用户确认状态，无一自动执行。

### 5.7 前端性能设计

清理结果动辄上万条文件，最初「任何交互都重建整个视图」的写法会造成明显卡顿。
现在的前端遵循三条约定（写在 `app.js` 顶部注释里）：

1. **视图只在切换页面或数据变化时重建一次**；
2. **勾选、展开、切换保留项等交互只做定点 DOM 更新** ——
   每个类目持有自己的节点引用（复选框、表体、徽标），
   点击时只改这几个节点 + 汇总数字，不再重跑 `renderView()`；
3. **长列表窗口化渲染** —— 文件清单只创建可视区域内的行
   （固定行高 30 px，滚动时用 `translateY` 平移并重绘窗口内约 30 行），
   2000 行的列表实际 DOM 只有 25 行。

实测（C 盘 50 万文件扫描结果，8 个类目）：

| 交互 | 耗时 |
| --- | --- |
| 勾选一个类目 | **1.2 ms** |
| 展开一个类目（首次建表） | **0.6 ms** |
| 勾选一个文件 | **1.2 ms** |
| 「选中全部安全项」 | **3.3 ms** |
| 切换左侧功能页 | **7.7 – 44 ms** |
| 清理清单实际 DOM 行数 | 52 行（窗口化前会是数万行） |

此外还做了两处细节优化：SSE 事件流正常时跳过兜底轮询（减少一半请求）、
扫描结束后默认只展开前 3 个类目（避免一次性创建大量表格）。

### 5.8 安全设计汇总

| 机制 | 实现 |
| --- | --- |
| 只监听回环 | `net.Listen("tcp", "127.0.0.1:0")`，随机端口 |
| 会话令牌 | 24 字节随机十六进制，注入页面 `<meta>`，`/api/*` 全部校验 |
| 扫描不改动 | 扫描阶段只读元数据，不打开文件内容（重复文件扫描除外，也只读） |
| 分级风险 | 受保护路径的勾选框被禁用；类目风险徽标前置展示 |
| 二次确认 | 每次清理都弹确认框，列出类目/文件清单、数量、体积、删除方式；永久删除需**再输入确认词** |
| 回收站兜底 | 默认移入回收站可还原；清空回收站需再次确认 |
| 白名单 | `%APPDATA%\KillTheC\config.json` 持久化；**扫描与删除两个环节都校验** |
| 管理员提权 | 非管理员时提供「提权」按钮，`ShellExecuteW("runas")` 重启自身 |

## 6. 打包与安装

### 6.1 主程序打包

```
go-winres simply --icon icon-256.png --manifest gui ...   # 生成 rsrc_windows_amd64.syso
go build -trimpath -ldflags "-s -w -H=windowsgui" .        # 产出 KillTheC.exe
```

- `-s -w` 去掉符号表与 DWARF 调试信息
- `-H=windowsgui` 去掉控制台窗口
- `-trimpath` 去掉源码绝对路径（避免泄露本机目录结构）
- `--manifest gui` 声明 `asInvoker`（按需提权），不强制 UAC

### 6.2 安装包打包

应用负载用 `gzip`（level 9）压缩后 `//go:embed` 进安装程序：

| 项目 | 体积 |
| --- | --- |
| KillTheC.exe（未压缩） | 7.17 MB |
| app.gz（gzip -9） | 3.00 MB |
| 安装器自身代码（Win32 + 解压 + 注册表 + lnk） | 2.26 MB |
| **KillTheC-Setup.exe 合计** | **5.02 MB** |

### 6.3 安装器实现要点

- **纯 Win32 原生窗口**：`RegisterClassExW` + `CreateWindowExW` + 自绘（GDI `RoundRect`/`DrawTextW`/`DrawIconEx`），
  不引入任何 GUI 库，因此安装器本身只有 2 MB 出头。
- **进度反馈**：解压线程通过 `PostMessageW` 回传百分比，UI 线程重绘，避免跨线程直接操作窗口。
- **快捷方式**：按 **MS-SHLLINK** 二进制规范直接生成 `.lnk`，
  包含 `LinkTargetIDList`（由 `ILCreateFromPathW` 取得真实的 shell 项目 ID）、
  `LinkInfo`（LocalBasePath）、`RELATIVE_PATH`、`WORKING_DIR`、`ICON_LOCATION`、`TerminalBlock`。
  生成结果的字段与结构经过与系统自带 `.lnk` 的逐字段对照验证。

  > 为什么不用 COM 的 `IShellLink`？实测本机 `IShellLinkW` 的虚表布局与文档顺序不一致
  > （`SetPath` 位置调用即崩溃，且 `GetPath` 回读为空），直接写二进制格式反而更可靠、更可控。
- **静默安装**：`KillTheC-Setup.exe /S`（可配 `/D=<目录>`），便于批量部署。
- **图标与 shell 刷新**：快捷方式写入采用「临时文件 + fsync + 原子改名」，
  并在写入后调用 `SHChangeNotify(SHCNE_CREATE|SHCNE_UPDATEITEM, SHCNF_PATHW|SHCNF_FLUSH)`
  让资源管理器立刻重新读取图标；安装收尾再调用一次 `SHCNE_ASSOCCHANGED`。
  这条刷新很关键——否则资源管理器可能在 exe 尚未落盘/被杀软扫描时读到失败结果并把占位图缓存住。
  快捷方式的 `ICON_LOCATION` 写成**不带 `,0` 的纯路径**，与系统自带快捷方式一致。
- **图标资源生成**：`go-winres` 直接消费 256×256 PNG，由它自行生成
  各尺寸的 RT_ICON（≤128 用 DIB、256 用 PNG）。
  ⚠️ 不要把自行拼接的 .ico 交给 go-winres——实测它对手写 DIB 条目的解析会产出损坏的小尺寸资源。
- **卸载登记**：写入
  `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\KillTheC`
  （DisplayName / DisplayVersion / Publisher / DisplayIcon / InstallLocation /
  UninstallString / QuietUninstallString / EstimatedSize / NoModify / NoRepair / InstallDate），
  以及 `...\App Paths\KillTheC.exe`（让「运行」对话框可直接启动）。

### 6.4 卸载实现

`UninstallString` 指向 `"<安装目录>\KillTheC.exe" --uninstall`。执行时：

1. 把自身复制到 `%TEMP%\KillTheC-Uninst-<时间戳>.exe`（避开「自己删自己」的文件占用）
2. 由临时副本以 `--uninstall-run <安装目录>` 启动，展示卸载界面
3. 结束仍在运行的主程序 → 删除快捷方式 → 删除注册表两项 → 删除安装目录 → 删除用户配置（可选）
4. 用 `MoveFileExW(MOVEFILE_DELAY_UNTIL_REBOOT)` 登记自删，并尝试立即删除

支持 `--uninstall --silent` 完全静默卸载。

## 9. 已知限制

1. **`C:\Windows\WinSxS` 不参与扫描**：组件存储使用大量硬链接，逐个统计会严重失真且极慢，
   已在「受保护区域」中说明。
2. **需要管理员权限的系统目录**：普通权限下这些文件会显示为删除失败（已在结果中列出原因），
   可通过内置提权解决。
3. **扫描时不打开文件内容**：分类完全基于路径、扩展名、体积、时间。若文件被改名成无关扩展名，
   分类会落在「其他」。
4. **NTFS 硬链接**：重复文件扫描按路径比对，同一文件的多条硬链接会被视为重复。
   默认排除系统目录与 `WinSxS`，实际影响很小。
5. **WebView2 缺失的极端环境**（如精简版系统）会降级为 Edge `--app` 窗口，界面一致但窗口边框为浏览器样式。
6. **不支持 FAT32 回收站**：此类分区上的删除会退化为永久删除（界面上仍按回收站流程提示）。
7. **整盘重复扫描耗时较长**：需要逐个读取文件内容比对，文件多时可能几分钟；
   界面上有实时进度与「停止」按钮，也可以改用「仅个人目录」范围。
8. **桌面快捷方式图标依赖系统图标缓存**：程序已在安装时主动通知 shell 刷新；
   若仍显示旧图标，重启资源管理器或执行一次 `ie4uinit.exe -show` 即可。

## 10. 构建方式

```bash
# 一键构建（首次运行会自动获取 Go 工具链到 .tools/go，约 10 秒）
bash build.sh

# 产物
dist/KillTheC-Setup.exe
```

构建脚本会自动完成：获取 Go 工具链 → 安装 `go-winres` → 生成资源 → 编译主程序 →
压缩负载 → 编译安装程序 → 校验体积是否 ≤ 20 MB。

> 构建依赖：Windows x64、可访问 `goproxy.cn` 的网络。
> 除 Go 工具链与 `go-winres` 外无第三方依赖（WebView2 绑定是纯 Go 实现，不走 cgo）。

## 11. 接口一览（本地 HTTP）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/system` | 权限、磁盘卷、回收站占用、配置、版本 |
| GET/POST | `/api/config` | 读取 / 更新偏好（主题、模式、重复文件阈值） |
| POST | `/api/whitelist/add`、`/whitelist/remove` | 白名单增删 |
| GET | `/api/fs/list?path=` | 应用内目录浏览（文件夹选择器） |
| POST | `/api/scan` | 启动全盘扫描 → 返回任务 ID |
| POST | `/api/dupes` | 启动重复文件扫描 |
| POST | `/api/residue` | 启动残留扫描 |
| POST | `/api/clean` | 执行清理（`files[]` 精确删除 或 `categories[]` 整类清理） |
| POST | `/api/recyclebin/empty` | 清空回收站 |
| GET | `/api/job?id=` | 查询任务状态与最终结果 |
| POST | `/api/job/cancel` | 中止任务 |
| GET | `/api/events?id=&token=` | SSE 实时进度 |
| POST | `/api/system/elevate` | 以管理员身份重启 |

除 `/api/events`（令牌走查询参数）外，所有接口都要求请求头 `X-KTC: <token>`。
